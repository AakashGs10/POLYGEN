# PolyGen-RAG

Natural-language-conditioned polymer generation. A user asks for a polymer in
plain English ("high Tg, low density"); the system parses that into a property
constraint block, generates candidate repeat units conditioned on those
targets, and scores them with a property Oracle — closing the loop by
rejection sampling / latent optimization until candidates meet the request.

## Architecture (runtime order)

```
text query ──▶ Tier 1: RAG parser ──▶ {Tg: >150, Density: <1.0, ...}
                                           │
                                           ▼
                        Tier 2: Conditional VAE  ──▶ candidate SELFIES
                                           │
                                           ▼
                        Tier 3: Oracle (property predictor)
                                           │
                              accept / reject / re-steer
```

## Build order (this repo is built backwards from the data)

You cannot build Tier 1 first — there is nothing downstream to feed. Each phase
produces the artifact the next one consumes.

| Phase | What it builds | Deliverable | Status |
|-------|----------------|-------------|--------|
| 0. Data foundation | PI1M ingest, SMILES→SELFIES, vocab, splits | `data/processed/{train,val,test}.csv`, `vocab.json` | ✅ in repo |
| 1. Oracle (Tier 3) | Open Polymer Challenge labels → Morgan/descriptor features → gradient-boosted regressors (scaffold-split) | `models/oracle/*.pkl`, `baseline_report.json` | ✅ in repo |
| 1b. Pseudo-labelling | Oracle labels all of PI1M → C-VAE training set | `data/processed/cvae_train.csv` | ⚠️ analysis script present; label-generation script TODO |
| 2. VAE pretrain (Tier 2a) | Unconditional seq-VAE on PI1M SELFIES | `models/vae.pt` | ⬜ not yet in repo |
| 3. C-VAE (Tier 2b) | Condition on property vector, fine-tune | `models/cvae.pt`, `generate.py` | ⬜ not yet in repo |
| 4. RAG parser (Tier 1) | retrieval (char-ngram TF-IDF over an exemplar corpus) → strict JSON constraint block, grounded in the data's property quantiles | `parse("high Tg") → {...}` | ✅ in repo |
| 5. Closed loop | text → parse → C-VAE → Oracle → constraint-satisfaction check (`src/pipeline.py`) | demo | ✅ CLI; UI pending |

## Key design decisions

- **SELFIES cannot encode polymer wildcards directly.** `*CC*` → `EncoderError`.
  The two connection points are swapped to `[At]` before encoding and swapped
  back on decode (`src/data/chem.py`). Every molecule is required to have
  **exactly two** endpoints, both before and after the round-trip.
- **"100% valid molecules" ≠ "100% valid polymer repeat units."** SELFIES
  guarantees a decodable molecule, not that two endpoints survive. The
  two-endpoint check is enforced at preprocessing and must be re-applied as a
  generation filter in Tier 2.
- **PI1M has no property labels.** A Conditional VAE needs (structure, property)
  pairs, so the real flow is: train Oracle on the Open Polymer Challenge set →
  pseudo-label all of PI1M with the Oracle → train the C-VAE on the
  pseudo-labelled set.
- **Scaffold splits for the Oracle, random splits for the VAE.** Random splits
  inflate Oracle metrics because near-identical backbones land on both sides;
  `src/oracle/features.py` does a Murcko-scaffold split.

## Running

```bash
pip install -r requirements.txt

# Phase 0 — data foundation
python src/data/download.py                 # fetch PI1M (~48 MB)
python src/data/preprocess.py               # full 1M; pass a number to limit, e.g. 30000
python src/data/vocab.py

# Phase 1 — Oracle (needs Open Polymer Challenge train.csv in data/raw/)
python src/data/properties.py
python src/oracle/train_baseline.py
python analyze_pseudolabels.py              # after PI1M is pseudo-labelled

# Tier 1 — natural-language -> constraint block (no torch needed)
python src/rag/parser.py "high Tg, low density"

# Closed loop — text -> generate -> score (needs a trained C-VAE)
python src/pipeline.py "heat resistant but lightweight" 200
```

`data/` and `models/` are gitignored — they are regenerated by the commands above.
